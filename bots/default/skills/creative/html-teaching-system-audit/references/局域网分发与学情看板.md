# 局域网分发 + 实时学情看板（微机室场景）

单文件 HTML 课件在微机室通过局域网 IP 分发，老师机双服务实时看学生机操作。全部脚本放课件同目录，双击即用。

## 架构（两个 Python 服务，无第三方依赖）

| 脚本 | 端口 | 职责 |
|---|---|
| `局域网分发.py` | 8000 | `SimpleHTTPRequestHandler`（`directory=` 指向课件目录）+ `ThreadingTCPServer`（allow_reuse_address）。学生机访问 `http://<老师机IP>:8000` 得到文件列表。`end_headers()` 加 `Cache-Control: no-store` 保证学生每次拿最新版。`log_message` 打印 `[HH:MM:SS] <学生IP> <GET 路径>` 实时访问日志。启动时用 UDP 8.8.8.8 探测本机局域网 IP（`s.connect(('8.8.8.8',80)); getsockname()[0]`），打印学生访问地址。 |
| `学情收集.py` | 8001 | 自定义 Handler：`POST /beat` 收下报告（学生 IP 自动落库进 `学情数据.json`），`POST /quiz` 收课堂检测成绩单（同落库，看板显示得分），`GET /` 返回看板页（脚本内嵌 HTML 模板生成 `学情看板.html`），`GET /data` 返回 JSON。每 5 秒轮询刷新；统计卡（在线/平均进度/总星数/平均时长）+ 可排序表格（IP、系统徽章、年级、进度%、⭐、得分、时长、最后上报时间）；**在线窗口用 90 秒**（非 30 秒）——学生切走标签页/做别的时浏览器会把 25s 心跳节流到 ~60s，30s 窗口会把活跃学生误判成离线灰点；看板上同时显示在线绿点与最后上报时间，教师可自己判「走神 vs 真离线」。心跳节奏 25s 不变。CSV 导出。 |

## 注入到课件的上报探针

- 注入位置：`</body>` 前，marker `<script id="__AGNES_XL__">`，幂等（已有 marker 就跳过）。
- **协议守护**：探针首行判 `location.protocol` 不是 http/https 就 return；再判 hostname 是纯 IP 才上报。效果：双击 file:// 时探针静默跳过，离线能力零影响；只有通过 `http://IP:8000` 打开时上报到 `http://IP:8001/beat`（IP 取自 hostname）。
- **报什么**：`document.title`（识别打开的系统）+ 所有 key 匹配 `/save|dash|prof|streak|exp|star|study|xq|score|progress|quiz|learn/i` 的 localStorage 值（各截 5000 字符）。不要求课件改代码——各系统存储键名不统一，收集端用正则尽力提取。
- **节奏**：`visibilitychange` 回前台 + 每 25s 间隔 + `pagehide` 时各触发一次；20s 节流。XHR POST，全部 try/catch，失败静默（学生机断网不影响学习）。

## 收集端正则提取规则

从上报的 localStorage 字符串里抓数字：`"progress"\s*:\s*(\d+)`、`"stars?"\s*:\s*(\d+)`、`"score"\s*:\s*(\d+)`、时长 `(totalMinutes|studiedMinutes|totalStudy)`。提取不到就存 0——**在线状态/IP/打开的系统/最后上报时间 100% 准确，进度数字仅参考**。报告里说清楚这个边界。

## 课堂检测成绩单（/quiz）

检测版交卷时额外 POST `:8001/quiz`（带 percent/等级/得分/用时/各题型得分率），收集端落库同 IP，看板该 IP 行多一列「检测分」。教师用它核对课堂测效果，配合 CSV 导出存档。

## 学情收集端：成绩记录被心跳冲掉（数据碰撞）— 高频坑

看板显示「不是当前成绩」的根因：`/beat` 心跳处理对 `data[ip]` 做**整条替换**（`data[ip] = {新字段...}`），而检测版交卷走 `/quiz`（结构化成绩单）。`/quiz` 没做独立解析、且之后的 `/beat` 不停覆盖 `data[ip]`，把 quiz 成绩字段冲掉 → 看板回退到 0 分。修复两条铁律：
- **`/quiz` 与 `/beat` 分路径解析**：`/quiz` 把 `report` 结构化存进 `rec["quiz"]`（percent/grade/got/full/time/lesson/ts），单独 print「检测成绩」日志；`/beat` 只走 localStorage 正则提取。
- **心跳用「合并而非整条替换」**：`rec = data.get(ip, {})` 先取旧记录，`if payload.get("file"): rec["file"]=...`、`if prog: rec["progress"]=prog`（各字段非空才写），`rec["ts"]=now`，`quiz` 字段天然保留。规则：任何「事件 A 会覆盖事件 B 的高价值字段」的落库，都先 `data.get(ip,{})` 再按字段合并，绝不 `data[ip]={全新 dict}`。
- 看板加「检测成绩 / 检测课时」列 + 顶部「平均检测成绩·N人交卷」统计卡，让 `/quiz` 数据一眼可见；CSV 导出同步加这几列。

## 探针 URL 铁律：跨端口 XHR 必须绝对地址（高频致命坑）

探针从 `http://IP:8000` 页面跨端口 POST 到 `:8001` 时，目标**必须带协议拼完整绝对地址**：`var S=location.protocol+"//"+m[0]+":8001"`。若漏写协议写成 `var S=m[0]+":8001"`，浏览器按**相对 URL** 解析，心跳/交卷全部打到当前 8000 分发器（返回 501），学情 8001 永远收不到任何数据。诊断指纹：8000 访问日志里出现 `POST /IP:8001/beat 501`（路径带 `:8001` 这种怪串就是相对解析的铁证），而 8001 的 `学情数据.json` 恒为空 `{}`。修复后学生端必须 `Ctrl+Shift+R` 强刷（`Cache-Control: no-store` 只保证下次取到新版，不失效已缓存页）。

## 服务重启铁律：先杀干净再拉（Windows 多进程同端口）

Windows 上 `allow_reuse_address=True` 的 ThreadingHTTPServer 允许多个进程同时 bind 同一端口——旧进程没杀干净就重启，新旧进程共存、请求被随机分发（行为时灵时不灵）。流程：`netstat -ano | findstr :8000` 列出所有 LISTENING 的 PID → 逐个 `taskkill /F /PID` → 确认只剩 1 个 → 再启动。声称「服务已就绪」前必须过此闸门。**注意**：Windows 上 bash 的 `kill`/`taskkill` 对 python 进程常无效，可靠杀法是 `powershell -Command "Get-NetTCPConnection -LocalPort 8000,8001,8002 -State Listen | Select -ExpandProperty OwningProcess | Sort -Unique | ForEach-Object { Stop-Process -Id $_ -Force }"`；杀完 `Get-NetTCPConnection` 复查为空才启动新进程。

## 并发写原子性（ThreadingTCPServer 多线程服务必做）

`学情收集.py` / `看班中心.py` 用 `ThreadingTCPServer`，每个请求独立线程。`load()/save()` 无锁时，N 个学生同时上报 = N 个线程各读一份旧 json、各写回 → **后写的把先写的记录整条覆盖丢掉**（症状：学情数据.json 时全时缺、看板上某台学生机记录时有时无，学生越多丢得越厉害）。诊断指纹：并发测试发 20-30 条 `/beat`，成功数 < 总数且 `学情数据.json` 记录数远少于上报数。修复铁律：
- 模块级 `_LOCK = threading.Lock()`；写路径用 `update(fn)` 辅助——**锁内完成 load→修改→save 原子三步**，不在锁外 load；读路径（`GET /data`）也持锁读（避免读到 `os.replace` 中途态）。
- 验证：发 30 条并发 `/beat` 必须 30/30 全 200 且数据文件记录数对得上；失败条数 > 0 即说明锁没覆盖全部写路径。

## 分发器 send_head 必须 URL 解码中文路径（v4 修复）

浏览器访问中文文件名 `http://IP:8000/信息科技八年级_课堂检测系统.html` 时，实际请求路径是**百分号编码** `%E4%BF%A1%E6%81%AF...`。`SimpleHTTPRequestHandler.translate_path` 对编码路径在 Windows 上处理不稳（v3 实测部分编码 URL 返回 0 字节/404，症状=「点课程卡片里面没内容」）。修复：`send_head` 里先 `decoded = urllib.parse.unquote(self.path)`，**用解码后的文件名做业务判断**（考试模式过滤、隐藏文件 404），再交 `super().send_head()` 走标准文件流。卡片首页的 `href` 也要 `urllib.parse.quote(文件名)`。规则：分发器任何按文件名做判断的逻辑，一律对 `unquote(self.path)` 的结果判断，不对原始 `self.path` 判断；验证必须用 `urllib.parse.quote` 拼编码 URL 实测返回字节数（> 10KB 才算文件真发出来了，0 字节 = 路径处理 bug）。

## 防火墙验证铁律：本机回环自测无效

`127.0.0.1`/`localhost` 回环**不走 Windows 防火墙**，老师机自测 200 ≠ 学生机可达。学生机打不开的排查顺序：① `netsh advfirewall firewall show rule name=all dir=in` 确认 8000/8001/8002 入站规则存在 → ② 学生机 `ping 老师机IP` → ③ 学生机浏览器访问。放行用 `netsh advfirewall firewall add rule name=教学系统8000-8002 dir=in action=allow protocol=tcp localport=8000,8001,8002`（持久化，换 IP 无需重放）；`一键启动.bat` 头部可加自提权（`net session` 检测 + `powershell Start-Process -Verb RunAs` 重跑自身），教师双击一次点 UAC「是」即完成全部放行。

1. `python 局域网分发.py`（后台）→ `urllib` GET 127.0.0.1:8000 和局域网 IP:8000，确认目录页 200 且文件清单完整。
2. `python 学情收集.py`（后台）→ GET /health 200；POST 一条模拟 /beat（带假 localStorage 样本）；GET /data 确认字段提取正确；再 POST 模拟 /quiz 确认检测分入库；**再发一条 /beat 确认 quiz 成绩字段没被心跳冲掉**（回归上面数据碰撞坑）。
4. 服务重启前跑「先杀干净再拉」闸门（见上节）；8001 看板为空但手动 curl 正常时，先查 8000 访问日志有无 `POST /…/beat` 501（探针相对 URL 坑）。
3. 探针注入后：每个 HTML 过一遍 Node `new Function` 语法扫描（含探针的新 script 块）。

## 防火墙/端口要点

- 先查 `netsh advfirewall firewall show rule name=all dir=in` 里 python.exe 有无放行规则；本机 8000/8001 被占用就换端口，探测法 `socket.connect_ex(('127.0.0.1', PORT))`。
- 学校 IP 每次开机可能变（DHCP）：两个脚本都自动探测并打印当前 IP；学生机照新 IP 输。要固定就在老师机设静态 IP。
- 端口选择：8000=分发、8001=学情，写死在脚本顶部常量里；改端口要同步改探针里的 `:8001` 与检测版里的 `:8001/quiz`。
