# 看班中心 · 微机室教师实时管理（小橙看班升级版）

用户要「类似小橙看班但更强」的班级/课堂管理小程序时，按此类做。小橙看班 = 教师多班级管理 App（全屏/定向通知、学生回复、课表、考勤、考试时钟、消息聚合）。微机室版做成**纯局域网 Python 服务**（无第三方依赖，双击即用），比原版多：实时在线监控 + 检测成绩聚合 + 考试时钟全局同步 + 全屏弹屏通知。

## 形态（三个文件 + 一个数据文件，放 `{{WORKBUDDY}}\内容中心\课程\教学系统\看班中心\`）

| 文件 | 角色 |
|---|---|
| `看班中心.py` | 服务，端口 8002（`ThreadingTCPServer` + 标准库 `http.server`），启动自动 UDP 探测本机 IP 并 webbrowser 开老师控制台 |
| `老师控制台.html` + `teacher.js` | 老师机浏览器面板：发通知 / 在线监控 / 检测成绩 / 一键考勤 / 考试时钟 |
| `学生端.html` + `student.js` | 学生机浏览器（`http://IP:8002/s`）：登录（姓名+班级）→ 收通知/回复/考试倒计时/心跳 |
| `看班数据.json` | 全量落盘：notices/replies/quizzes/heartbeat/attendance/exam/classes/students，可备份导出 |

## 服务接口（`看班中心.py`，全部纯标准库）

- `POST /api/notify {title,text,scope("all"或班级),full(bool),at?(定时ms),by}` → 通知入列；`at` 在未来则进 `scheduled` + `threading.Timer` 到点发布（定时任务）。
- `POST /api/reply {nid,user,klass,text}` → 存进 `replies[nid]`（**list**，先 `.get(nid,[])` 再 append，别把 `replies` 存成 list 型再 `.get`）。
- `POST /api/heartbeat {user,klass,score?}` → 学生 20s 心跳，`heartbeat[ip]` 存 user/klass/last/agent，看板 30s 内 last = 在线（绿点）。
- `POST /api/quiz {user,file,report{percent,grade,got,full,time,lesson}}` → 检测成绩入列（与 8001 学情收集同名语义，可并存）。
- `POST /api/attendance {action:"list",klass}` 查名单；`{klass,students:[{name,present}]}` 保存点名，同时快照 `attendance[时间戳+班级]={list,ts,present,total}`。
- `POST /api/exam {action:"start",minutes,label}` 置 `exam={label,start,end}`；`{action:"stop"}` 清 `exam`。学生端轮询到 `exam.end` 本地算倒计时（最后 5 分钟变红闪）。
- `POST /api/classes {classes:[...]}` 维护班级清单（控制台「＋班级」走它）。
- `GET /api/all`（老师端全量 + 带 online 标记的 hb）、`GET /api/student`（学生端：notices+replies+exam+classes）、`GET /` `GET /s` 返回对应 HTML。
- **数据读写加 `threading.Lock`**（ThreadingTCPServer 每连接一线程，`load()/save()` 里 save 必须持锁 + 写 tmp 再 `os.replace` 原子替换）。注意 `load()` 初始化时 `replies` 必须是 `dict`（曾因历史 json 存成 list 导致 `/api/reply` 崩）。
- **静态 .js/.css 文件路由（高频致命坑）**：HTML 页面引用独立脚本（`<script src="teacher.js">` / `student.js`）时，`do_GET` 里必须有静态文件路由——`p.endswith(".js")` 时读 `os.path.join(ROOT, os.path.basename(p))`，存在则按 Content-Type 返回，否则 404。漏写这条 = 页面 JS 全 404，老师控制台/学生端打开后**整个界面没反应**（无报错、无加载、按钮全死），且服务端日志干净（404 不显眼，容易误判为前端 bug 去翻 HTML/JS）。规则：交付「HTML + 独立 .js」形态的服务后，**GET 每个 .js 端点实测 200** 才算验证通过；.js 文件放服务 `ROOT` 目录（与 .py 同目录），不另开目录。

## 学生端要点

- 登录页：选班级 + 填姓名/座位号 → `localStorage` 存 `XQME`，刷新免登；退出清掉。
- **通知弹窗策略**：只有 `full`（全屏）或 `scope===all` 的新通知才强制全屏弹屏（大字号、8s 自动关、Esc 可关）；定向到本班的普通通知进列表不强制弹，避免打扰。首次进入把已存在的通知全预置进 `seen`，只对新增的弹。
- 轮询：`poll()` 每 4s 拉 `/api/student`，`heartbeat()` 每 20s POST；考试倒计时用独立 1s `setInterval`（`exam.end` 在本地算，不依赖服务端时钟）。
- 检测系统交卷时 `POST :8002/api/quiz` 与 `:8001/quiz` 并存（两个老师侧都可收）。

## 课中监控（不只交卷后）：检测版心跳带「本课进度」

`/quiz`（交卷成绩）只在交卷那一刻上报——老师要看**课中**谁做了几题、卡在哪，必须让检测版**心跳**（`__AGNES_XL__` 探针，25s 一次）也带上「本课已答数/总题数」。做法：检测版探针把原生 `beat()` 换成增强版 `_xlBeat`，每拍算一个 `xq = {lesson, answered, total}`（answered 遍历当前课 `qs` 数 `app.userAnswers[progressKey]` 非空者），随 `/beat` 一起 POST。老师侧 8001 学情看板加一列「📖 本课进度 answered/total 题」，不依赖交卷就实时看到每台学生机答题进度。规则：检测版探针必须复用课件同一套 `progressKey(app.currentUnitIdx, app.currentLessonIdx, i)`，否则 answered 数对不上。

## 数据碰撞（同 8001 学情收集，铁律相同）

`/api/heartbeat` 等高频接口对 `看班数据.json` 的记录**按字段合并、不整条替换**，否则 quiz/notice 等高价值字段被心跳冲掉。服务侧任何写接口先 `d = load()`、改目标子结构、`save(d)`，不 `d = 全新 dict`。

## 验证流程

1. `python 看班中心.py`（后台）→ GET `/`、`/s` 返回 200；**再 GET `/teacher.js`、`/student.js` 必须 200 且字节数 > 100**（静态 .js 路由缺失 = 页面全没反应，见服务接口节静态路由坑）。
2. `curl`/`urllib` 逐个 POST：`/api/notify`（含 full + 定时各一条）→ `/api/reply` → `/api/heartbeat` → `/api/quiz` → `/api/attendance`（list + save）→ `/api/exam`（start + stop）。
3. `GET /api/all` 确认 hb 带 online、quizzes/attendance 落库；`GET /api/student` 确认 notices 过滤 + exam + classes 正确。
4. 前端两页面过 `node --check`（teacher.js / student.js 是独立 .js 直接查）；HTML 内联脚本另查。

## 防火墙/端口要点

- 8002 独立端口，与 8000（分发）/8001（学情）不冲突，可三个一起开。
- 启动日志打印本机局域网 IP（DHCP 会变，每开课前看一眼黑色窗口第一行）；要固定就在老师机设静态 IP。
- 先 `netsh advfirewall ... dir=in` 确认 python.exe 放行；端口被占换常量，探测法 `socket.connect_ex(('127.0.0.1',PORT))`。

## 交付边界（报告里说明）

- 老师控制台「全屏通知」按钮只做**本端预览**（真全屏弹屏发生在学生端，不在老师机）。
- 检测成绩/学情的「进度数字」是尽力提取，**在线状态/IP/系统名/检测分 100% 准确**。
- 看班数据.json 是唯一事实源，导出/备份靠它；学生机断网不影响学习（所有上报 try/catch 静默）。
