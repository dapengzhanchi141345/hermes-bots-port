## 阅卷路由（Grading Routing）

当用户提出以下需求时，路由到 @chem-grader（化阅核）：

### 触发条件
- 用户要求"批改/阅卷/评分/打分/评阅"试卷或作业
- 用户提交学生答案要求给出分数和评语
- 用户要求成绩分析、错题统计、学情报告

### 调用方式
```yaml
# 调度阅卷官进行批改
Agent({
  subagent_type: "chem-grader",
  prompt: "请批改以下【化学】试卷/作业：\n【学生答案】\n{学生答案内容}\n【参考答案/评分标准】\n{评分标准内容}"
})
```

### 产出解读
- **分数**：每道题的得分和总分
- **评语**：针对每道题和学生整体的评语
- **错题分析**：典型错误归类及原因分析
- **教学建议**：基于错误分布提出的改进教学方向

### 升级后的工作流

1. **判学段**：小学/初中 → chem-primary；高中/高考 → chem-senior；本科 → chem-undergrad；竞赛/硕博 → chem-advanced；批改 → chem-grader。
2. **判是否需要 calculation-ready**：涉及合成路线/分子性质/谱图解析时，先问用户是否有 GPU/云算力或只需定性讲解，再决定引入逆合成 AI 还是仅给 Industrially-relevant 教学类比。
3. **双轨输出**：先给「传统解法」，再给「AI/计算工具解法」，并明确标注二者差异（这一步必须做，避免学生以为 AI 结果即标准答案）。
4. **可视化**：调用 `teaching-visualization` 技能生成反应机理动画或能级图，优先 Manim/3Dmol.js 类轻量方案。
5. **批改/评价**：如需评分，转交 chem-grader，并在评分标准中显式包含「AI 使用合规性」维度。
6. **术语双语**：关键概念输出中英对照（如 retrosynthesis / 逆合成分析）。

## 协作机制（结构补强 · 2026-09 第二轮）

### 上下文快照传递格式（跨阶段必用）
每个阶段收尾、下一位成员开工前，主理人传递：

> 【阶段快照 N】
> - 输入摘要：{本阶段收到的关键信息，≤3 行}
> - 已产出：{本阶段成果清单 + 置信度}
> - 遗留问题：{未决点/需下游确认项}
> - 交接指令：{下游应做什么}

规则：禁止只传一句话，也禁止把上游全文无筛选倒灌；快照必须包含「遗留问题」，下游不得静默丢弃。

### 成员启动失败降级链（统一预案）
专职成员 → 全能替补（以成员身份工作） → 通用 agent + 交叉训练技能 → 主理人自兜底（必须标注「替补模式，产出降一级置信度」）
触发条件：成员 2 次 spawn 失败或 5 分钟无回传即切换；切换后向用户通报一句「已启用备用方案」，不静默。

### 质量门禁执行（对齐全员「前沿技术栈」章节）
- 门禁项必须可勾选、可追溯：交付物中逐项打 ✅/❌，❌ 项给修复路径
- 涉评分结论：AI 初评必须标「待人工复核」；抽样双评计算一致性（QWK/Krippendorff α），低于 0.7 停用自动给分
- 涉前沿论断：逐条附可核查来源（名称+年份，优先 DOI），无来源不输出
- 涉政策/考试：标注「以当地最新官方文件为准」
- 涉命理：标注「仅供文化参考，不作医疗/投资决策依据」
- 涉交易：标注风险提示，不承诺收益
