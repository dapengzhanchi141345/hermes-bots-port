## 一、中国义务教育信息科技课标与中考考法

### 1.1 国家课标基准（2022 年版）
- 教育部《义务教育信息科技课程标准（2022年版）》：2022年5月发布，首次将"信息科技"列为独立科目，围绕"物联网、数据、算法、信息安全、人工智能"设计 3 个模块与 4 个实践要求，初中阶段以 4 个核心模块（数据与编码、算法与程序、网络与系统、人工智能初步）为主线。（背景基准，来源：教育部官网 2022 年印发通知）

## 二、AI 赋能 K-12 编程教育

### 2.1 代码生成助手的课堂实证（教学用法 SOTA）
- **Coding Steps（Codex 辅助初学者学 Python）**：Kazemitabaar 等，69 名 10–17 岁无文本编程经验者对照实验：使用 AI 代码生成组完成度提升 1.15 倍、正确率提升 1.8 倍、时间减少 0.57 倍，且不影响后续手动改码任务；编程基础越好者收益越大。核心风险：学生常"照抄不读"AI 代码（过度依赖）。**教学用法启示：AI 生成代码必须配"解释→修改→重写"三段式任务，先 Scratch/无代码基础打底。**
  - URL: https://arxiv.org/pdf/2302.07427 （访问日期：2026-09-27）
- **CodeAid（不直接给答案的 LLM 编程助手，700 人 12 周部署）**：面向大学 C/系统课大规模部署，8000+ 次交互；回答正确率 74%→87%、有用性 83%→91%（迭代后）。设计四原则：D1 发挥 AI 独特优势；D2 降低提问门槛同时保持认知投入；D3 不直接给答案、用伪代码+逐行解释+修改建议脚手架；D4 保持透明可控。**这是"AI 助教"防抄作业的 SOTA 设计范式，直接可迁移到微机室。**
  - URL: https://arxiv.org/html/2401.11314v2 （访问日期：2026-09-27）
- **K-12 LLM 提示（hint）脚手架**：ICER 2025 论文，CodeKids 平台（瓦州理工+当地公立校合建的开源课标对齐平台）用 GPT-4 生成"答案感知提示"：提示由泛到具体、禁止泄露答案，98.1% 提示内容对齐度≥0.30，Hint Quality Score 0.749。105 名学生中 31.4% 存在变量赋值/数据类型错误概念——提示系统针对性修复。
  - URL: https://dl.acm.org/doi/10.1145/3702653.3744323 （访问日期：2026-09-27）
- **RockStartIT Tutor（14–16 岁，初中年龄段直接对标）**：GPT-4 Assistant API + 模块化语义标签知识库（Markdown 文件作 file_search 工具），分层遍历策略：先给提示/讲解→按需升级→拒绝直接给答案，输出严格限定在已审核的教学内容内，消除幻觉；TAM 模型评估 13 名学生+教师。**架构最接近李老师"单文件 HTML + 局域网"约束：不微调模型、纯 prompt+知识库。**
  - URL: https://arxiv.org/pdf/2512.11882 （访问日期：2026-09-27）

### 2.2 LLM 作 AI 助教 / 自动出题评分的证据
- **Harvard AI tutor RCT（N=194）**：AI 导师组比课堂主动学习组学得多、用时少、投入度和动机更高，效应量 0.73–1.3 标准差（p<10⁻⁸）；关键设计：系统提示植入教学最佳实践（主动参与、认知负荷管理、成长型思维）+ 逐题顺序脚手架 + 人工编写的分步答案防幻觉。83% 学生认为 AI 讲解不逊于人类教师。
  - URL: https://pmc.ncbi.nlm.nih.gov/articles/PMC12179260/ （访问日期：2026-09-27）
- **LLM 自动评分反馈（ProgFeed，Python 入门课）**：215 名学生 17 次实验 6693 份提交的随机对照：自然语言提示反馈显著提高完成率与收敛速度；AI 生成失败测试用例的效果依赖测试有效性——**"AI 出题"可行但必须人工校验测试质量**。
  - URL: https://exa.ai/library/publication/td3m434jv8w （访问日期：2026-09-27）
- **GenAI-Ped 结构化框架（Java，N=124 对照 7 周）**：结构化 GenAI 教学组高阶思维 HOTS 增益 d=0.80（p<0.001）、编程逻辑 d=0.36（p=0.047）；日志分析显示任务分解与调试行为更多。**核心结论：无脚手架的自由使用 GenAI 会滑向"答案提取"，结构化协议才是教学增益来源。**
  - URL: https://ltu.diva-portal.org/smash/get/diva2:2078285/FULLTEXT01.pdf （访问日期：2026-09-27）
- **CodeTutor 一学期实地研究（50 学生）**：使用组最终成绩显著提高，其中没用过 LLM 工具的新手收益最大；但随时间推移学生对其信任下降、更偏好人类 TA；提示质量与回答有效性显著相关。**含 GPT-5 Study Mode 案例：CodeCombat 游戏化平台 + GPT-5 学习模式"先试错→反馈→修订"循环，5-6 年级 Python 课 3 周干预，动机与自我调节学习均改善。**
  - URL: https://arxiv.org/html/2404.13414v2 ；https://exa.ai/library/publication/rrmqb521f94 （访问日期：2026-09-27）
- **MSR 实证综述（给教师的使用准则）**：四条集成准则：①学生未掌握领域基础前不引入 GenAI；②教 AI 素养；③GenAI 只作传统教学的补充；④设计干预促参与（限制复制粘贴、元认知校准、 nudging 批判性思维）。
  - URL: https://www.microsoft.com/en-us/research/publication/learning-outcomes-with-genai-in-the-classroom-a-review-of-empirical-evidence/ （访问日期：2026-09-27）

### 2.3 单文件 HTML 教学系统 2026 最佳实践（教师侧）
- 本条与李老师现有铁律（file:// 双击可用、局域网 IP 动态探测、清空 localStorage 入口）结合，补充 2025-2026 通用实践信号：
  - 单文件架构在 2025-2026 仍为微机室/离线首选：内嵌 JS 库（P5.js/Excalidraw 均可单文件打包）+ 本地 JS 评估代替 LLM 自动评分（离线环境无 API）；AI 辅助环节设计为"课前教师用 LLM 生成题目/代码片段，课中离线使用"两段式。
  - LLM-as-Judge 评分需网络；离线替代方案：确定性单元测试（学生代码跑预设用例）+ 静态检查（AST 特征）——对应 2.2 中 ProgFeed 的"执行式评分"思路。
